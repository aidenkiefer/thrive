# Maintain the Thrive GitHub Project

GitHub Issues hold implementation tickets. GitHub Projects shows their current status, priority, lane, and release target. The repo holds architecture decisions, acceptance criteria that span tickets, and historical QA evidence. Link to those documents from the issues. Basecamp is for church coordination and approvals. Reference the relevant decision or milestone from GitHub when useful.

1. Find the existing Thrive project and link it to `aidenkiefer/thrive`. When none exists, create a private `Thrive Website` project under the repository owner's account. Check the project's visibility before adding items. A board's visibility does not make issues in a public repository private.
2. Search existing issues and open pull requests before creating any ticket. Use one issue per deliverable and link any existing PR. Include an outcome, owner or lane, prerequisites, acceptance criteria, and links to evidence. Use only public-safe content in this repository's issues. For visitor feedback, file an actionable summary with personal details removed.
3. On the [Thrive Website board](https://github.com/users/aidenkiefer/projects/3), use the Delivery stage field for Backlog, Ready, In progress, In review, Blocked, and Done. Keep the built-in Status in sync by mapping In progress and In review to In Progress, Done to Done, and the remaining stages to Todo. Mark dependencies using issue relationships or a dependency link on the issue. Use Ready once prerequisites are satisfied, In review once a PR is ready for QA, and Done once the recorded acceptance criteria are met. A green branch build alone does not complete release verification.
4. At session start and handoff, reconcile active tickets with branches, PRs, and review evidence. Record blockers and next owners in the ticket. Keep status synchronized in GitHub rather than maintaining a second backlog in Basecamp or Markdown.

For board changes the authenticated GitHub CLI needs Projects write access. If it is missing, the owner can run `gh auth refresh -h github.com -s project`. Start with `gh project list --owner aidenkiefer` and use the returned project number. See [GitHub Projects documentation](https://docs.github.com/en/issues/planning-and-tracking-with-projects/automating-your-project/using-the-api-to-manage-projects?tool=cli).
