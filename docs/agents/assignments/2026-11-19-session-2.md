## The pipeline (every ticket, every lane)

```
Ready -> Build -> Gate -> PR (template) -> Independent QA -> Fix loop -> Merge -> Docs -> Next ticket
```

1. **Build.** Own worktree and `<tool>/<lane>-<slug>` branch (`scripts/agents/worktree.sh new <tool> <lane>-<slug>`), `git branch --show-current` before the first edit. Use the `lane-builder` skill. Plan first for M tickets. Delegate read-only exploration and test-writing to subagents; keep the main context for decisions. Move the board card to **In progress**.
2. **Gate.** `scripts/agents/gate.sh` must pass before every push. Record real numbers in the PR body (tests, files, lines), never estimates.
3. **PR.** Open from the template, set the milestone, run the `scribe` skill (fast model) for the session log and PR body. Move the card to **In review** and comment `QA-READY #N` plus the one-line risk summary on the PR. Use `gh api -X PATCH repos/aidenkiefer/thrive/pulls/N -F body=@file` (not `gh pr edit`; `gh` needs the sandbox's all-permissions mode).
4. **Independent QA (never the author's own session).**
   - Claude's PRs and Codex's PRs: reviewed by **Cursor** through a fresh `senior-qa` subagent on a different model family from the author, in a throwaway worktree.
   - Cursor's PRs: reviewed by **Codex** (`/review` or a fresh reviewer session) on the PR branch; if Codex is busy, Cursor launches a subagent of a different model family and records that in the QA note.
   - Auth, schema, migrations, redirects and anything touching the live database get a second family or an explicit "single reviewer" note.
   - QA writes a PR comment: verdict (MERGE / FIX-FIRST / BLOCK), findings as blocker / should-fix / nit with file and line, the commands run, what is unverified. QA never pushes to the author's branch.
5. **Fix loop.** Author fixes should-fix and blocker items, re-gates, pushes (`--force-with-lease` on rebased branches), comments `FIXED`, QA re-checks only the delta.
6. **Merge (Cursor as senior QA).**
   - **Standing owner go (this session):** squash-merge docs, tests, Experience and Ops PRs after a MERGE verdict and a green `gate` check. `--squash`, never `--delete-branch` on stacked bases; retarget dependents with `gh api -X PATCH .../pulls/N -f base=main`.
   - **Needs an explicit owner go on the issue, every time:** any Data-stack PR; any migration, seed, or live database write; anything touching auth, secrets or env; redirect activation (#63); a new runtime dependency. If unsure, ask.
   - Nobody merges a PR they authored.
7. **Docs.** After each merge QA appends the PROGRESS row and, for decisions, `owner-decisions.md`; the board card goes to **Done**; the builder's session log is already in the PR. QA keeps `docs/agents/qa/<date>-*.md` for every multi-PR review.
8. **Next ticket.** Take the next item in your lane's list below without waiting. When your list is empty take the first **Ready** card for your lane on Project 3 (filter Lane, Delivery stage = Ready). If nothing is Ready, write one line in your session log ("lane idle, nothing Ready") and tell the owner; do not invent work or edit another lane.

**Blockers go to the owner with a decision card** (what, why, options, a recommended default), posted on the issue and in chat, not buried in a log.

**Live database writes** follow `docs/ops/supabase-live-project.md` rule 3 (owner go naming the artifact, backup confirmation, Claude as sole executor, ledger row).
