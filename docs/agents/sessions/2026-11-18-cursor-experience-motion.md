# Session log: `cursor/experience-motion`

**Assignment:** owner request 2026-11-18 ("tasteful animations and transitions, subtle but noticeable, smooth, performant, responsive") · **Lane:** experience · **Tool:** cursor · **Stacked on:** `cursor/experience-draft-handoff` (PR #24)

## Entries
- `22:40` **decision**: CSS-only motion, no new dependency, no client JavaScript. Everything animates `transform`/`translate`/`opacity` (compositor-only), uses one shared easing (`--ease-out`), and is gated by `prefers-reduced-motion`. Scroll reveals use native scroll-driven animations (`animation-timeline: view()`); browsers without support (currently Firefox) show static content, so nothing is hidden by a failed script. The `translate` property is used so reveals compose with hover `transform` on the same element.
- `22:45` **change**: motion system in `src/app/globals.css`: scroll reveals (`.reveal`, `.reveal-stagger`, `.reveal-late`), hero load-in (`.hero-enter`: text staggers; the h1 only slides, no fade, so it paints immediately for LCP), hero photo settle plus a light scroll parallax (`.hero-bg*`), card lift on whole-card links (`.motion-lift`, hover devices only), button press and 1px hover lift (`.press`), mobile drawer entrance (`.drawer-in`), and smooth anchor scrolling with a sticky-header offset.
- `22:50` **change**: applied to the content kit (SectionIntro, FeatureSplit, PullQuote, StepList, CtaBand, MapEmbed, CardGrid, PeopleGrid), homepage sections, list pages (groups, outreach, sermons, series), `PageHero`, buttons (shared Button, LinkButton, hero and nav actions, newsletter), nav underline slide, and card links (event, sermon, upcoming events, InfoCard links only).
- `22:55` **note**: verification on a production build in a real browser: 25 reveal elements on `/` start hidden below the fold and all finish at full opacity when scrolled into view; reveals use ViewTimeline, parallax uses ScrollTimeline; 12 routes at 1280px and 375px have zero stuck-hidden elements and no horizontal overflow; with `prefers-reduced-motion: reduce` all content is visible, 0 scroll-driven animations, 0 running animations, smooth scroll off. Gate PASS (50 tests, 4 pre-existing lint warnings).
- `22:55` **note**: not verified: data-backed list grids with real records (empty without a database; same classes apply), Firefox/Safari rendering, real-device frame rate, Lighthouse/CLS numbers. Transform and opacity changes cannot shift layout, so CLS risk is low but unmeasured.
- `22:55` **note**: decided against a page-to-page fade transition: a `template.tsx` opacity fade would delay LCP on every navigation, and Next's view-transition support is still experimental.
- `23:15` **decision**: independent senior QA review found a blocker in the first version: a route-group `loading.tsx` made real 404s on dynamic detail pages return 200 with `noindex` (the Suspense boundary flushes the shell before `notFound()` runs), which would break the WordPress-to-Next URL migration. Removed `loading.tsx` and the `.skeleton` CSS. If a loading state is wanted later, wrap only the data-fetching part of list pages in `<Suspense>` and keep every `notFound()` outside it; never add `loading.tsx` at a segment that has a `[slug]` child.
- `23:15` **change**: QA fixes: `.press` hover/active no longer apply to disabled buttons (`:not(:disabled)`); `data-scroll-behavior="smooth"` on `<html>` (Next 15.5 dev warning, behavior change in Next 16); the groups, outreach and series list cards now use `motion-lift` like the other link cards.
- `23:15` **note**: not changed: very tall `.reveal` elements fade more slowly because `animation-range` is a percentage of the element's height (a `min(40%, 320px)` cap is untested); `box-shadow`/color/filter are also transitioned on buttons and cards (hover feedback), so "only transform and opacity" describes the scroll and entrance effects.
