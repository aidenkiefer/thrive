## Bugs fixed

1. **Sermon `published_at` had no timezone** (`parse-current-exports.py`). WordPress `post_date` is site-local, written as `2024-03-10 10:00:02`. Postgres would read it as UTC, 5–6 hours early. The parser now attaches the Chicago offset (`2024-03-10T10:00:02-05:00`). All 120 sermons changed; verified against `post_date_gmt` (check 5).
2. **Visitor-facing schedule text was raw export codes** (`parse-current-exports.py`). `recurrence_description` was `Every 7 weekly`, `Every 14 weekly`, `Every 1 custom_days`. It is now built from the rule fields only: weekly every 7 days → the weekday (`Wednesdays`); every 14 → `Every other Thursday`; `certain_weekdays` → the named days; `custom_days` / `advanced` → `Selected dates`. All 25 recurring events changed. Nothing is invented: the weekday comes from the rule's start date.
3. **Seed re-runs moved every series' `published_at` to "now"** (`scripts/seed-current.ts`). It is now the earliest `published_at` of the series' sermons, so re-runs are stable.

## Seed re-run behavior (static review of `seed-current.ts`)

- Every table upserts on a natural key: `slug` for speakers, series, sermons, and both event tables; `(recurring_event_id, start_datetime)` for occurrences, backed by the unique index from the D3 migration. A second run with the same `parsed/` files writes the same values and creates no duplicates.
- It never deletes. Re-parsing on a later day shifts the 90-day occurrence window; older occurrences stay but are hidden once past (public queries read `start_datetime > now`).
- **Owner note:** a re-run **overwrites admin edits** on any imported record (same slug) for every column the seed writes. Seed once, then edit in admin. Re-seed only before editing starts.
- The seed is all-or-nothing per row, not per run: if it stops midway, re-running is safe and finishes the rest.
